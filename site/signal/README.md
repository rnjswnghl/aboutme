# 예고 신호 점검기 (마지막 과제 B · 13번 앱)

10번 논문 「미리 주는 화면 테두리 신호는 반응을 빠르게 하는가」의 측정 방법과 판정 규칙을 그대로 쓰는 앱입니다.

> 게임·앱을 만드는 사람이 ‘곧 나온다’ 예고 효과를 넣을지 정할 때, 이 앱은 자기 기기에서 신호 있음·없음을 섞어 재고 논문의 판정 규칙으로 ‘빨라졌다’와 ‘차이를 확인하지 못했다’ 가운데 하나를 알려 줍니다.

- 공개 주소: https://aboutme-rnjswnghl.vercel.app/signal/ (로그인 없음)
- 소개 사이트 대표작 자리: https://aboutme-rnjswnghl.vercel.app/#featured

## 사용자가 할 일 세 가지

1. **한 판 재기** — 신호(기본은 논문 값: 예고 500ms, 점등 100ms, 테두리 10px)를 고르고 40초 동안 노란 원이 뜨면 누릅니다.
2. **판정 읽기** — 테스터 여러 명의 ‘신호 있음 중앙값 − 없음 중앙값’을 모아 HL 추정치·95% 신뢰구간·단측 Wilcoxon p와 판정을 봅니다.
3. **신호 바꿔 비교** — 간격이나 두께를 바꿔 다시 재면 신호별 판정이 나란히 놓입니다.

## 논문에서 가져온 것

| 논문(reflex-hub) | 이 앱 |
|---|---|
| `web/src/games/reaction/config.js` 한 판 14회(조건별 목표 6 + 캐치 1), 첫 판 연습 4회, 대기 800~2000ms 짝맞춤, 반응 창 1500ms | `runner.js` 같은 구조 |
| `runner.js` 프레임 예약, 이벤트 timeStamp, 탭·포커스 이탈 감지 | `runner.js` 같은 방식 |
| `analysis/run_analysis.py` 유효 시행(100~1500ms), 제외(합 10회·조건별 5회 미만), 참가자별 중앙값 차이, Hodges–Lehmann과 정확 신뢰구간, 단측 Wilcoxon, 판정(p < .05 이고 HL < 0) | `stats.js` 같은 규칙 |
| 한계 1·3·4 | 화면 ‘이 판정이 말하지 않는 것’과 전략 점검 경고 |

논문은 아직 데이터 수집 전이라 결론 숫자가 없습니다. 그래서 이 앱은 논문의 결론이 아니라 **방법과 판정 규칙**을 사용자의 데이터에 적용합니다.

## 데이터와 비밀값

- 기록은 사용자의 브라우저(localStorage)에만 남고 서버로 보내지 않습니다. 서버·DB·AI 호출이 없습니다.
- ‘예시 데이터’는 고정 난수로 만든 가상 테스터 21명(‘예시 A1’…)입니다. 실제 사람의 응답이 아닙니다.
- API 키·토큰·비밀번호가 없어 환경 변수도 필요 없습니다.

## 실행 묶음으로 돌리기

1. `signal-check.zip`을 새 폴더에 풉니다.
2. `signal/index.html`을 브라우저로 엽니다. 설치할 것은 없습니다. (글꼴은 인터넷이 없으면 기본 글꼴로 보입니다. 논문 PDF 링크는 공개 주소에서만 열립니다.)
3. 판정 코드 시험: Node 18 이상에서 `node tests/signal-stats.test.cjs` → `통과: scipy·논문 코드 대조 31건, 규칙 점검 4건`

기준값(`tests/stats-cases.json`)은 `python3 tests/gen_cases.py <reflex-hub 경로> tests/stats-cases.json`으로 논문 분석 코드와 scipy 1.18에서 만들었습니다.
